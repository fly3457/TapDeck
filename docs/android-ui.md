# Android 0.3.16 主界面

参考微信输入法的浅灰键盘样式，按安全视口宽度计算尺寸。`W`、`H` 是扣除系统栏及刘海安全区后的应用视口宽、高；系统时间、电量和导航栏正常显示。

## 高度

| 区域 | 尺寸 |
|---|---|
| 顶部连接栏 | `0.10W` |
| 底部内容 | `0.60W` |
| 底部上下间距 | 各 `0.01W`，底部总高 `0.62W` |
| 全键盘 | 四行均分，行间距 `0.01W` |
| 非全键盘 | 快捷键、语音各占 `0.30W` |
| 触控板 | 剩余高度 `H − 0.72W` |

两种模式共用同一个底部容器，切换不移动触控板或底部边界。快捷键 1–4 项为一行，5–8 项为两行，第二行保留未使用的列。控制区不滚动，电脑列表与设置对话框按需滚动。

0.3.14 新安装默认启用八项，按顺序为：音量- `VolumeDown`、上 `Up`、音量+ `VolumeUp`、退格 `Backspace`、左 `Left`、下 `Down`、右 `Right`、回车 `Return`。PC 新配置与 Android 未同步前的默认值一致；连接后仍以 PC 保存并同步的配置为准，升级保留既有配置。0.3.14 曾按用户要求替换当时电脑的八项配置并保留备份；本轮继续保留已有配置。

0.3.7 快捷键与全键盘统一使用 `0.01W` 的横向间隙、行间距和四周外边距。上外边距复用底部原生容器已有的 `0.01W`，不重复添加；快捷键区底部留出 `0.01W` 再进入语音区。受限窗口只按下面的缩放系数缩小纵向间距。

当 `H < 0.82W` 时，纵向尺寸、字号和图标乘以 `H/(0.82W)`；按键宽度仍按视口宽度计算，触控板保留至少约 `0.10W × 缩放系数` 的高度。视口或安全区变化时重新测量；像素取整允许 1–2 px 差异。

## 样式

- 底部、快捷键、语音区统一浅灰 `#DCDDDF`；普通键白色，特殊键 `#B6B9C2`。
- 圆角半径为 `0.0125W`，浅色细边加轻微底部阴影。按下、Shift 激活、空格录音保持蓝底白字反馈。
- 主键位近黑 `#111216`，字号 `0.05W`；空格、Ctrl 等多字符键字号 `0.04W`。副键位灰色 `#929796`、字号 `0.028W`，比 0.3.1 放大约 27%。主副标签作为一组在键面居中，两者之间留 `0.002W` 间距，副键提示不再贴住上沿。
- 空格保留“空格”文字，麦克风使用 Lucide `mic-audio-lines` 矢量图标。
- Shift、Enter、Backspace 分别使用 Lucide `arrow-big-up`、`corner-down-left`、`delete`；Shift+Enter 并排组合前两个图标。图标统一 2 单位线宽、大小 `0.05W`，按下或 Shift 激活时变白，不使用 emoji 或字体符号。
- 顶部文字字号 `0.032W`，图标大小 `0.055W`，图标点击区域各宽 `0.10W`。保留电脑名、状态和已连接时的 RTT；长文字省略。
- 主界面尺寸和文字按宽度换算，补偿系统字体缩放；连接、配对弹窗保持系统字体规则。

0.3.2 将第四行首键从 Alt 改为左 Ctrl，可长按搭配其他键。0.3.6 普通键宽从 8.5% 改为 8.9%，横向间隙和左右外边距各为 1%；Shift / Backspace / Shift+Enter 为 13.85%，Ctrl / Enter 为 18.8%，空格为 33.65%，第二行继续居中。行间距为 1%，上下外边距复用底部容器已有的 1%，键盘内部不重复增加留白。按累计边界取整分配像素，第一、三、四行完整铺满；受限窗口只缩小纵向尺寸。其余键值、字体、配色及长短按语义保持原样，详见 [全键盘](full-keyboard.md)。触控板仍为黑底白字，0.3.3 将手势提示分为两行，增加双指缩放和三指窗口操作；标题和提示按宽度计算，高度受限时整组缩小并居中。具体行为见 [触控板手势](touchpad-gestures.md)。

## 应用图标

0.3.6 增加与 PC 相同风格的蓝底白色方块应用图标：蓝色为 `#175CD3`，不增加文字。普通兼容图标沿用 PC 的 32×32 网格和白色方块范围；自适应图标使用 108dp 图层及居中的 48dp 白色方块，API 33+ 提供同形的单色层。Manifest 设置 `android:icon` 与 `android:roundIcon`，用于桌面、应用列表和系统应用信息；外轮廓由系统圆形或圆角方形蒙版决定。图标资源均为原生矢量，依据 [Android 自适应图标规范](https://developer.android.com/develop/ui/compose/system/icon_design_adaptive)。

## 连接入口

右侧 Lucide `plug` 图标点击后打开“连接与设置”，标题下显示来自 BuildConfig 的版本名和版本号，例如 `TapDeck 0.3.16（19）`，再下一行是可通过浏览器打开的 `github.com/fly3457/TapDeck`。顶部可控制手机按键震动并测试，震动区与配对区分割线上下各留 16dp。配对区先显示“管理电脑（数量）”，再显示“输入PC连接窗口URL”及同排右对齐的扫码图标，下一行为网址输入框。小屏或大字体下内容可滚动；录音准备、传音和停止处理中禁用“连接”，显示“请先结束语音输入”。

0.3.16 顶部名称区域显示“电脑名称 ▾ · 状态”，点击整个名称区域展开可滚动的电脑列表。优先显示备注名，当前项置顶并有选择标记；其他电脑按添加顺序显示，名称下方为地址和“已配对”或“需重新配对”。列表末尾提供“添加电脑”“管理电脑”。录音期间可查看列表，选择及添加操作禁用；管理页仍可改备注或忘记非当前电脑。备注清空恢复系统名称，忘记前显示明确的电脑名称和地址。更多行为见 [多 PC 配对与切换](multi-pc.md)。

点击扫码图标打开竖屏扫码，首次使用请求相机权限；扫描 PC 的配对二维码后自动回填网址，弹窗保持打开，点击“连接”才发起配对。取消扫描、拒绝权限或识别到其他二维码不覆盖已有网址；无相机设备仍可手动输入。PC 自动弹出首次配对确认框；拒绝、关闭或超时后手机显示原因，停止本次自动重试，需再次点击连接；已配对设备的正常重连不变。

未连接图标为橙色 `#F59E0B`，每 3 秒连续弹跳 3 次，最高幅度 `0.012W`，后两次高度为首次的 50% 和 25%，每次往返时长依次为 440 / 310 / 220 ms；上升减速、下落加速，模拟小球弹跳；连接成功变为绿色 `#22C55E` 并复位。

只有页面前台、连接、电脑列表、电脑管理、灵敏度或配对弹窗均未打开、且未连接时播放提醒。连接成功、打开弹窗或切入后台后，立即停止并复位；再次需要提醒时重新等待 3 秒。

## 设备灵敏度与按键反馈

触控板左上角增加 Lucide `sliders-horizontal` 图标，点击打开本机灵敏度滑块和旁边的倍率数值。默认 `1.0×`，范围 `0.5×–3.0×`，步长 `0.1`，提供“恢复 1.0×”。未连接时也可以设置，调节立即生效；本机 DataStore 保存设置，重开、切换电脑或忘记配对不重置。

0.3.5 删除弹窗中的“0.5× 慢速”“3.0× 快速”和“立即生效，并保存在这台 Android 设备上”说明，保留滑块、当前倍率与恢复默认。

`1.0×` 采用此前 PC 灵敏度 `2` 的基准；Android 发送鼠标位移时再乘本机倍率。PC 移除可编辑灵敏度，旧配置及协议 v2 中的 `sensitivity` 固定为 `2`，保证旧客户端的基准速度。新 Android 不读取 PC 灵敏度来决定鼠标速度。双指滚动、缩放步进和手势识别阈值不受倍率影响。

图标放在原生触控板父容器的独立按钮中，与触控板表面分别按指针 ID 分发；点击图标取消待发轻点并释放拖拽，避免设置按钮生成鼠标操作。按钮随受限窗口缩小，仍位于触控板内部；其余区域尺寸不变。

快捷键、全键盘和语音触发控件共用振动服务。Android API 29 及以上直接发送设备调校的 `EFFECT_CLICK`，长按副键、Shift 锁定、按键保持及长按录音实际生效时发送 `EFFECT_HEAVY_CLICK` 再反馈一次；平台提供不支持效果的回退。API 26–28 直接调用 `Vibrator` 发送 15 / 30 ms 单次震动，使用设备默认强度。松手、取消、自动重复和另一触摸区域的手指不产生额外反馈。语音模式按钮及顶部键盘模式切换也有轻震。

手机顶部连接图标 →“连接与设置”顶部的“按键震动反馈”默认开启，独立保存在当前设备；下方保留实心“测试震动”按钮。用户确认实体手机在关闭系统震动开关后 App 仍可震动，0.3.8 因此移除“系统震动设置”入口。PC“设置与状态”提供手机入口说明；PC 没有此设备本地开关。使用普通 `VIBRATE` 权限，无运行时授权弹窗。

0.3.7 不再读取系统触感开关来拦截请求，也不修改手机系统设置。API 33+ 使用模拟实体遥控器按键的 `USAGE_PHYSICAL_EMULATION`；较旧版本直接使用 `Vibrator.vibrate(effect)`。Android 14 模拟器在关闭系统触感或将触感强度设为 0 时仍完成请求。系统总震动开关、硬件反馈强度、勿扰及厂商策略仍可能限制马达输出，无法保证所有手机在所有设置下都震动；不使用需要特权的绕过标志。测试提示“已发送测试震动”只表示请求已发送，无马达或调用失败时分别提示。API 定义及系统策略见 [VibrationAttributes](https://developer.android.com/reference/android/os/VibrationAttributes) 和 [AOSP VibrationSettings](https://github.com/aosp-mirror/platform_frameworks_base/blob/android14-release/services/core/java/com/android/server/vibrator/VibrationSettings.java)。

## 语音区

模式按钮与按键采用相同的白底、圆角、细边和阴影。模式行高 `0.07W`，底部提示区高 `0.045W`，录音控件直径 `0.12W`。可拖动范围预留模式行、底部提示和电平环，不会压住文字。

0.3.10 配置切换按钮单独居中，旁边不再显示操作说明。空闲时底部单行显示“按住说话，松手结束 · 可拖动到区域任意位置”或“轻点开始，再点结束 · 可拖动到区域任意位置”。激活录音后（准备、传输、停止阶段），该行改为“麦克风电平 42% · 对应操作说明”；准备／停止时通常为 0%。横向电平条位于语音区顶边，即快捷键与语音区之间，高 `0.004W`，按原电平的 2 倍长度显示（最大为整行），不再占用最底部。底部百分比仍显示原电平，音频音量保持不变。

0.3.9 顶部按钮显示 PC 当前配置的自定义名称。启用 2–3 组时按固定顺序轮换；只启用 1 组时显示灰色禁用按钮，点击无操作与震动；全部关闭时显示“语音未启用”，录音控件禁用。准备、录音、停止阶段禁止换组，PC 此时更名或停用不会改变这一轮的名称、类型与结束热键。0.3.16 起组 ID 按 PC 分别保存在加密目录，控件位置仍为手机级设置；升级时旧选择归属原配对电脑，优先匹配旧长按／单击类型。详见 [三组语音配置](voice-profiles.md)。

长按组为圆形，按住 300 ms 开始、松手结束；单击组为方形，轻点开始、再点结束。长按空格使用当前选中组并始终松手结束：长按组保持／释放组合键，单击组分别发送开始／结束热键；不把空格录音当作单击常驻录音。全部关闭时空格仍能输入空格，不能开始录音。

0.3.7 单击录音的准备、传输或停止阶段，触控板左／右击只结束录音并消费本轮按下与抬起，不向电脑发送鼠标点击；停止完成后，下次点击才操作鼠标。长按录音仍可同时操作触控板。收到 PC 的 `mic_stopped` 或 `mic_error` 时，手机停止采音、丢弃待发音频并同步复位按钮和电平；按录音 ID 匹配，过期回复不能结束新的录音。

## 构建与验收

Android 版本为 `0.3.16` / code `19`，包名与签名不变。交付构建通过 `scripts/build-windows.ps1 -OutputDirectory dist/0.3.16`，Windows EXE 嵌入本次构建的 `TapDeck-0.3.16.apk`，PC“关于”页分别显示接收端与内嵌 Android 版本，版本来自根目录 `version.properties`，允许两端独立演进。独立 Android 构建也生成带版本号的 APK，同时保留 `TapDeck-debug.apk` 兼容路径。

- JVM 测试覆盖正常、受限和极小视口，以及语音控件边界、连接提醒周期和取消。触控板状态机覆盖延迟单击、第二次按下／松手时机、拖拽、长按、取消、指针 ID、滚动方向、缩放锁定及三指一次触发。设备设置测试覆盖默认值、倍率边界、无效值、读取与调节竞态、写入顺序、关闭时保存及设备独立性。反馈策略覆盖本机开关实时变化、无马达、失败和异常，避免重复请求。
- 键盘几何测试覆盖按键宽度、间隙、四周留白、第二行居中及像素取整，短窗口与极小尺寸不得越界或重叠。
- Android 测试覆盖 1/4/5/8 项快捷键、两种模式边界、33 个键面实际宽度／间距、连接图标动画和设置入口，并生成截图；按键回归包含 Ctrl 短按、多指 Ctrl+C、Shift 单次大写、Enter、Shift+Enter、空格语音和退出清理。图标测试检查 PackageManager 读取结果、蓝白配色、48dp 前景范围和单色层，并输出系统／圆形／圆角方形／单色预览。
- 设备或模拟器验证结果记录在 [验证记录](verification.md)。实际手机的触感、字体显示和语音识别由真机验收确认。

0.3.16 的五种配置共通过 49 项回归，电脑列表覆盖零台、一台、多台、同名和长名称、滚动、修改备注与单独忘记；录音三个阶段均验证切换、扫码和外部 Intent 限制，拒绝的链接立即消费，避免页面重建后重放。另在普通屏和小屏 130% 字体下各完成一次扫码入口回归。使用 `scripts/test-android-multipc.ps1` 可运行加密迁移、管理界面及三个独立接收端的链路专项测试。

在已启动的 Android 模拟器上运行 `powershell -File scripts/test-android-ui.ps1 -Serial emulator-5560` 可重复矩阵验收。脚本拒绝对实体设备修改显示参数，完成后恢复原始尺寸、密度和字体设置。日志与截图默认保存在 `dist/android-<Android版本>/screenshots`（自动读取版本清单）。各配置验证快捷键 1% 间距、灵敏度入口、滑块上下限、恢复默认、重新打开后的保存、反馈开关与测试按钮；正常、小屏 130% 字体及受限窗口重复验证触控板时序、双指缩放、三指滑动、语音区独立手指分发和按键反馈次数。正常配置额外检查振动服务中 `CLICK` / `HEAVY_CLICK` 的 PHYSICAL_EMULATION 完成记录，验证 App 关闭时不发送、系统触感关闭时仍可请求；该用例仅在模拟器临时调整触感设置，结束后恢复。语音回归检查消费鼠标点击、陈旧回复隔离及真实 AudioRecord 线程的停止。

矩阵覆盖 1080×2400 / 字体 100%、720×1280 / 字体 130%、640×960 / 字体 130%、1404×1872 / 字体 100%，以及宽 1080 px、高度限制为 600 px 的应用视口。截图中的电脑连接、快捷键配置和交互回调来自测试模拟，不表示完成了真实电脑输入或音频链路验收。
