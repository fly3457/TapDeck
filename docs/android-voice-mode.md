# Android 语音模式与触控板配色（2026-10-07）

本次按需求改了 Android 端的语音触发方式和触控板配色，并在 ONYX Tab8C（Android 11 / API 30）上真机验证。

## 区域比例

四个区域严格按屏幕高度分配（`MainActivity.kt` 的 `Regions`）：

| 区域 | 比例 | Tab8C（1872 px）实测 |
|---|---|---|
| 状态（连接信息 + 语音/全键盘开关 + 连接按钮） | 10% | 0–187（固定高度，避免内部文字撑大区域） |
| 触控板 | 40% | 187–935 |
| 快捷键 | 25% | 935–1403 |
| 录音控件 | 25% | 1403–1872 |

录音控件在最后 25% 内可自由拖动；顶部 13% 留给标题，底部 14% 留给提示行与电平条，控件本身不会压住文字。触控板为黑底白字，语音输入区为偏深米黄背景（`MicBallView.BACKGROUND = #FDE6AF`）。

## 系统状态栏

窗口不再隐藏系统栏：`fullscreen()` 改为 `show(systemBars())` 并保留 `BEHAVIOR_DEFAULT`，因此顶部能看到系统的时间、电量、Wi-Fi 等；状态区通过 `WindowInsets.statusBars` 让位，不会被状态栏压住。`FLAG_KEEP_SCREEN_ON` 仍然保留。

## 顶部开关

- 位置：状态区右侧，紧邻「连接」按钮。
- 文字：「长按语音输入」/「单击语音输入」，字号与「连接」一致（按状态区高度自适应，上限 19 sp）。
- 间距：文字与开关之间 6 dp，开关与「连接」之间 16 dp。
- 外观：38×22 dp 蓝色/灰色轨道 + 白色圆点，点击切换。

## 录音控件形态

形状**只由当前模式决定**（不再跟随服务端返回的录音模式）：切换开关的瞬间控件形状就变，不需要等下一次录音。

| 模式 | 空闲 | 录音中 |
|---|---|---|
| 长按语音输入（圆） | 圆形 · 蓝 · 「长按」 | 圆形 · 红 · 「长按」 |
| 单击语音输入（方） | 方形 · 蓝 · 「轻点」 | 方形 · 绿 · 「单击」 |

长按模式下控件始终是圆形（空闲与录音中都是）；单击模式从空闲起就是方形。

## 底部行布局

语音区底部固定两行，电平条不再贴屏幕最下边：

| 位置（距区域底部） | 内容 |
|---|---|
| 22 dp | 水平电平条（5 dp 高，只画已填充部分，未填充处透出米黄背景） |
| 26 dp | 「麦克风电平 NN%」（录音时显示） |
| 8 dp | 提示文字「可拖动到区域任意位置」/「连接电脑后使用语音输入」（固定在最下） |

控件可拖动的下边界留出 14%（下限 26 dp）给这几行，因此把控件拖到底也不会压住它们。

语音输入区背景为偏深的米黄 `#FDE6AF`；该底色上文字改用暖灰 / 棕色（提示 `#8A7858`、电平 `#78603C`）。

## 单击/长按模式与快捷键联动

- **单击（免按）录音期间按任意快捷键会先结束录音**，这一次按键只用于停录、不再补发快捷键；长按模式下按键行为不变（录音由松手结束）。

## 语音区：模式开关 + 形状区分

语音区顶部右侧是模式开关（Compose `Switch`），文案分别是「长按语音输入」与「单击语音输入」，两种模式互斥，不再依赖“双击”切换：

| 模式 | 开关 | 触发控件 | 手势 |
|---|---|---|---|
| 长按语音输入（默认） | 关 | 圆形 | 按住达到 300 ms 开始，松手结束 |
| 单击语音输入 | 开 | 方形（约 12% 圆角） | 轻点开始，录音中再轻点结束 |

- 开关在状态区右侧（「连接」按钮旁），由 `CompactSwitch` 自绘，在 10% 高度内只占很小一块；画布的高度计算不再依赖开关行测量值，改用区域高度比例。
- 形状只表示当前模式，颜色继续表示状态：蓝＝可说话、橙＝准备中、红＝长按录音、绿＝单击录音、灰＝结束中 / 未连接。
- 录音时控件外圈显示麦克风电平进度环，底部保留电平条与百分比；空闲时底部提示「可拖动到区域任意位置」。
- 录音控件可拖动的垂直范围＝标题下方到区域底部（底部留出提示与电平条空间），水平为整宽，位置与之前一样保存在 Android 本地。
- 长按真正开始录音时会自动把开关切回「长按语音输入」，避免界面与实际模式不一致。

## 触控板配色

`TouchpadView` 背景改为黑色（`Color.BLACK`），主标题与操作提示改为白色 / 浅灰（`0xFFCBD5E1`），分隔线改为深灰（`rgb(60,66,74)`）。

## 真机验证（Tab8C，`adb -s 291C4856`）

| 步骤 | 结果 |
|---|---|
| `adb install -r dist/TapDeck-debug.apk` | Success |
| 启动后界面 | 触控板全黑、文字白色；快捷键按钮正常；语音区顶部右侧「长按语音输入」开关（关）+ 圆形「说话」控件 |
| 点开关切到单击 | 开关变蓝、文案变「单击语音输入」，控件变为蓝色方形，标题变为「单击语音输入 · 轻点开始 / 再轻点结束」 |
| 轻点方形控件 | 控件变绿、标题「免按录音 · 轻点停止」，PC `runtime-stats.json` 的 `audio_packets` 持续增长（麦克风在传音） |
| 再轻点 | 回到空闲，控件恢复蓝色 |
| 切回长按并按 3 秒 | 控件保持圆形并变红，标题「长按录音 · 松手停止」，外圈出现电平进度环 |
| 拖动控件 | 可拖到语音区顶部与底部（提示文字上方），松手后位置保存；重启后按保存值恢复 |
| 区域比例 | `uiautomator` 实测：状态 90–187（10%）、触控板 187–935（40%）、快捷键 935–1403（25%）、录音区 1403–1872（25%） |
| 系统状态栏 | 顶部可见系统时间、电量 91%、Wi-Fi/蓝牙图标；应用标题与「连接」按钮位于状态栏下方 |
| 顶部开关切换 | 开关与文案在「长按语音输入 / 单击语音输入」之间切换，文字与「连接」同号；控件同步在圆形 / 方形之间变化 |
| 单击录音中按快捷键 | 录音中的音频包计数在按键后停止增长（`audio_packets` 27377 → 27377），确认快捷键会结束录音 |
| 顶部开关 | 点击后开关与文案在「长按语音输入 / 单击语音输入」之间切换，控件同步在圆形 / 方形之间变化（开关可点区域约 90×90 px，位于状态区右侧） |

排查记录：一度出现“拖动无反应”，原因有两个且都已确认解决——一是先前的测试把触摸坐标按错误密度换算（本机 density 为 1.875，不是 3.0），二是 `pm clear` 后设备处于未连接状态。改用 `uiautomator dump` 读取真实 bounds 并重新配对后，拖动、单击、长按均正常。


## 已知取舍

- 模式选择不持久化：App 重启后回到默认的「长按说话」。这与需求中的“默认是长按说话”一致；若之后希望记住上次选择，可在 `PairStore` 里加一个布尔字段。
- 免按模式的开始 / 结束热键仍由 PC 端配置（当前为 `RightCtrl+L` 两次），Android 只负责发送 `mic_start` / `mic_stop`，协议未改动，仍为 v2。
