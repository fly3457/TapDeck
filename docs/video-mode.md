# 视频模式

视频模式把整块手机屏幕变成 PC 主显示器：画面上直接用触控板手势操作鼠标，并保留一个语音悬浮球。需要接收端与 Android 都为 **0.4.0** 或更新版本；PC 设置页“允许手机查看屏幕”开启（默认开启）。

## 进入与退出

连接电脑后，点击顶部栏键盘图标左侧的显示器图标进入。进入后隐藏顶部栏、快捷键与系统栏，整屏只显示 PC 画面；从屏幕边缘滑动可临时呼出系统栏。

按系统返回键／返回手势，或点击左上角半透明按钮退出。App 进入后台时停止传画面，回到前台后自动恢复；断线重连后同样自动续上。

顶部工具栏分两侧，位置固定，不随文字长短跳动。从 0.5.14 起整体下移约 60px（18dp），右上角只保留“更多”：

| 位置 | 按钮 | 作用 |
|---|---|---|
| 左上角 | ‹ 退出 · fps · 延迟ms | 固定宽度（窄屏竖屏时缩短，不与右侧图标重叠），超出显示“…”；退出视频模式，同时显示实际帧率与画面端到端延迟（0.5.11 起：PC 截屏到手机解码输出的一秒中位数，不含屏幕显示约 1–2 帧；旧版 PC 只能显示控制通道 RTT，前缀为“RTT”；窄屏竖屏时省去前缀，只显示毫秒数）。PC 光标移到其他显示器时，第二行显示“光标在其他显示器” |
| 右上角 | 更多（Lucide `ellipsis`） | 两段式开关：点一下在下方竖向展开，再点一下收起；点菜单里的图标或画面都不会收起。展开时，或收起后快捷键盘、全键盘、体感仍在生效时显示为蓝色；收起时有未读通知，右上角显示红点。从上到下：<br>· 铃铛（Lucide `bell`）：打开电脑通知列表，红色角标显示未读数，与普通模式顶栏的铃铛相同，见[电脑通知转发](notifications.md)<br>· 四宫格（Lucide `layout-grid`）：显示／收起快捷键盘<br>· 键盘（Lucide `keyboard`）：显示／收起全键盘<br>· “1:1”框（TapDeck 自绘）：恢复默认比例，回到刚连接时的状态（按高度填满、水平居中）<br>· 三维旋转（Lucide `rotate-3d`）：开启／关闭体感控制，见[体感控制](#体感控制)<br>· 扬声器（Lucide `volume-2` / `volume-x`）：打开／关闭电脑声音，见[电脑声音](#电脑声音) |

## 体感控制

从 Android 0.5.4 起，在“更多”菜单中开启体感控制后，转动手机即可平移画面，效果与单指拖动画面相同，鼠标不动：

- 向右转看到右边，向左转看到左边；
- 手机顶部朝自己倾斜看到上面，顶部向外倾斜看到下面（0.5.6 起按实测反转了上下方向）；
- 在桌面上原地旋转手机（绕屏幕法线）不参与；
- 横屏、竖屏都按屏幕方向换算。

实现使用陀螺仪（`TYPE_GYROSCOPE`）角速度。每弧度平移 1.2 个视图长边（0.5.8 曾整体降为 80%，0.5.9 按实测恢复）。平移只与转过的角度成正比：转得快慢只影响画面移动得快慢，同样转过一个角度始终移动同样的距离（0.5.6–0.5.9 曾有“快转移得更远”的加速度曲线，0.5.10 按用户要求去掉）。从 0.5.5 起增加防抖：

1. **One Euro 自适应低通滤波**（Casiez 等，2012）：缓慢或静止时截止频率约 1.2 Hz，压掉 8–12 Hz 的手抖；快速转动时截止频率随角加速度升高，跟手、不拖沓。
2. **平滑门限**：滤波后低于 0.05 rad/s 视为静止或零漂，不平移；0.05–0.1 rad/s 之间逐渐放开，起步不突跳；超过 0.1 rad/s（约 6°/s）原样计入，不扣减距离（0.5.10 起，此前为直接减去 0.05 rad/s）。

每次开始监听时滤波状态清零。转偏了可点“更多”里的“1:1”恢复默认比例，或单指拖回。（0.5.5–0.5.7 曾有“回归中心”按钮，0.5.8 起按用户要求移除。）单指拖动、捏合缩放与体感可同时使用，画面到边缘后停止。

传感器只在视频模式显示、App 在前台且开关打开时监听；退出视频模式或切到后台即停止，回来后自动继续。开关在本次 App 运行期间保留，不写入设置。没有陀螺仪的手机，该图标显示为半透明，点击提示不可用。

## 电脑声音

从接收端与 Android 0.5.15 起，视频模式会把电脑正在播放的声音一起转发到手机，适合在另一个房间用手机管理电脑。“更多”菜单最下方的扬声器图标可以随时关闭或打开，选择保存在手机上，默认开启；电脑端是旧版本时图标半透明，点击提示升级。

- 电脑用 WASAPI 回环采集默认播放设备的输出，不需要虚拟声卡。采集取自系统混音、早于电脑的音量与静音，所以电脑静音或调低音量时手机仍能听到；手机音量用手机的音量键调节。
- 插拔耳机、切换默认播放设备后自动跟随新设备。默认播放设备是 VB-CABLE 的 CABLE Input 时不转发：它播放的正是手机麦克风的声音，转发回手机会形成回声。
- 格式为 48 kHz 立体声 16 位 PCM，每 10 ms 一包，约 1.5 Mbit/s，局域网里可以忽略。没有声音播放时电脑不发送数据。
- 手机预缓冲 30 ms 后开始播放，积压超过 150 ms 时丢弃新包，声音不会越拖越晚；电脑端最多积压 100 ms。
- 手机正在语音输入时自动静音，避免手机喇叭的声音被麦克风录回电脑。切到后台或退出视频模式时停止。

## 快捷键盘与全键盘

两者互斥，打开一个会自动收起另一个，再次点击当前图标即收起；按住的键在切换、收起、退出或断线时全部释放。键盘只占自身区域，区域外仍是触控板，悬浮球始终在最上层。两者都以 50% 透明度叠加在画面上。

**快捷键盘**跟随语音悬浮球：显示在球正下方并水平居中，拖动悬浮球时一起移动；下方放不下时改到球上方，靠边时收在屏幕内。单个按键约 62×40dp：

| 方向 | 排列（8 个快捷键时） |
|---|---|
| 竖屏 | 竖着 2 列 × 4 行 |
| 横屏 | 横着 4 列 × 2 行 |

**全键盘**固定在画面底部：

| 方向 | 宽度 | 高度 |
|---|---|---|
| 竖屏 | 屏幕宽度 W | 与普通模式相同，0.62W（含上下留白） |
| 横屏 | 不拉满，取屏幕短边（与竖屏同宽），水平居中 | 纵向压扁，约 40% 屏高 |

快捷键与 PC 配置同步；全键盘的语音键同样使用第一个已启用的语音组。

## 画面规则

PC 画面在手机上从不旋转，横屏和竖屏使用同一条规则：**按高度填满、水平居中**。

| 手机方向 | 16:9 电脑画面的默认显示 |
|---|---|
| 竖屏（例如 9:20） | 高度占满，左右被裁掉，只显示中间部分 |
| 横屏（例如 20:9） | 完整显示，两侧留窄黑边 |

双指捏合以手指中心为焦点缩放画面，最小为完整显示整个 PC 画面，最大为 PC 像素的 3 倍（且至少为默认的 4 倍）。单指拖动平移画面，平移不会露出画面外的黑边；画面不随 PC 光标自动平移。旋转手机时重新套用默认规则，并尽量让光标留在画面内；工具栏的“恢复默认比例”回到刚连接时的状态。

## 手势

视频模式是直接操作：点哪里就操作哪里，单指不再相对移动鼠标。

| 操作 | 效果 |
|---|---|
| 单指按住拖动 | 平移手机上的画面，鼠标不动 |
| 单指轻点 | 鼠标移到点击位置并左击；与触控板相同，等待 300 ms 确认是否双击 |
| 双击 | 在第一次轻点的位置左键双击（第二次落点略有偏差也不影响） |
| 双击后按住并移动 | 在原位置按住左键，跟随手指拖拽，松手释放；可拖动窗口标题栏、框选、拖文件 |
| 三击及以上 | 双击后紧接着的轻点立即在同一位置点击，构成三击（如选中整行） |
| 单指长按（500 ms） | 鼠标移到按住位置并右击，带长按震动 |
| 两指轻点 | 在当前鼠标位置右击 |
| 两指移动 | PC 滚轮：开始滚动时先把鼠标移到双指中心，滚动的是手指下方的区域 |
| 两指张开／合拢 | 缩放手机画面（不发送 Ctrl＋滚轮） |
| 三指上滑／下滑 | 任务视图与桌面操作（手机系统开启三指截屏时会被系统截获，需在手机设置中关闭） |

点在画面之外（横屏两侧黑边）不操作电脑。点击位置换算为 PC 主显示器的物理像素，优先通过 FakerInput 虚拟 HID 绝对坐标鼠标点击：对 Windows 即真实鼠标，输入法候选框等忽略软件注入点击的窗口也能点中；未安装虚拟键盘时退回 SendInput 绝对坐标。每次点击先移入并悬停约 25 ms，再按下保持约 40 ms，与真实点击节奏一致。系统手势导航时，屏幕中部两侧边缘已尽量排除返回手势（Android 限制每侧最多 200dp）。

## 语音悬浮球

视频模式只保留一个语音入口：可拖动的悬浮球（直径约 51dp，比普通尺寸小 20%），位置单独保存在本机。它固定使用 PC 语音页中**第一个已启用的语音组**（新安装默认是单击语音输入 RightCtrl+L），不能在视频模式中切换组：

- 单击语音组：方形，轻点“说话”开始，再点“结束”。录音期间触控板的第一次点击只用于结束录音。
- 长按语音组：圆形，按住说话、松手结束。

颜色与电平环和下半区语音区一致；没有已启用的语音组时显示“禁用”。

## 画质

“连接与设置”中可选画质，下次打开视频模式时生效：

| 档位 | 输出 | 码率（60fps） |
|---|---|---|
| 流畅（默认） | 最高 1920×1080 | 约 12 Mbps |
| 清晰 | 原生分辨率，最高 2560×1440 | 约 20 Mbps |
| 省流 | 最高 1280×720 | 约 6 Mbps |

PC 画面只按比例缩小、从不放大，同时不超过手机 H.264 硬件解码器上限。只传 Windows 主显示器。

## 实现

| 环节 | 做法 |
|---|---|
| 截屏 | 内嵌精简 LGPL ffmpeg 的 `ddagrab`（DXGI 桌面复制），帧留在 GPU 上；`draw_mouse` 把光标画进画面 |
| 缩放 | 三级探测：`scale_d3d11` 在显存内缩放并转 NV12（零拷贝）→ 不缩放、编码器直接读取 ddagrab 显存纹理（零拷贝，旧驱动不支持 `scale_d3d11` 时；省流档与超出手机解码上限时跳过）→ 下载到内存 CPU 缩放 |
| 编码 | 每级依次探测 `h264_nvenc` → `h264_amf` → `h264_mf`（硬件 MFT，覆盖 Intel 核显）；结果按显示器、编码器与路径缓存，接收端启动后后台预热。超低延迟预设、无 B 帧、CBR、VBV 约 250 ms（避免关键帧过度量化在纯色背景上出现色块闪烁）、GOP 2 秒 |
| 封装 | FLV 到标准输出：每帧带长度，收到即可转发，避免裸 H.264 流等下一帧起始码的一帧延迟 |
| 传输 | 独立的证书固定 WSS `/video`，与控制连接分开，大帧不会阻塞心跳与点击；积压超过约 100 ms（6 帧）丢到下一个关键帧 |
| 解码 | Android MediaCodec 异步模式直接输出到 SurfaceView；开启 `KEY_LOW_LATENCY` 与厂商低延迟开关，输出帧到达立即渲染 |
| 缩放显示 | 只改变 SurfaceView 的布局尺寸与位置，由系统硬件合成器缩放，不额外拷贝像素 |

ffmpeg 子进程放在“随句柄关闭而终止”的作业对象里，接收端退出或崩溃时一并结束。同一时间只有一部手机能查看屏幕，另一部请求时提示“另一台手机正在查看电脑画面”。协议细节见[控制协议](../protocol/README.md#video)，构建方法见下文。

## 构建内嵌 ffmpeg

`scripts/build-ffmpeg.ps1` 下载固定版本的 FFmpeg 8.1.3、nv-codec-headers 11.0.10.3（NVIDIA 驱动 456.71 及以上）与 AMF headers 1.5.3 源码包。它先校验 SHA-256，并用 FFmpeg 官方发布密钥核对源码签名，然后在一次性 Docker Ubuntu 24.04 容器（默认使用 Canonical 在 ECR Public 发布的官方镜像）内用 mingw-w64 静态交叉编译。

构建过程会确认 GPL／nonfree 均未启用，且 `ffmpeg.exe` 只依赖 Windows 系统 DLL。产物与 `manifest.json`（版本、源码地址与哈希、configure 参数）写入 `windows/internal/video/assets`。`build-windows.ps1` 在交付前核对资源哈希、两个接收端 `--apk-info` 读回的 `ffmpeg_sha256`，并写入 `release-manifest.json`。许可证见[第三方声明](../THIRD_PARTY_NOTICES.md)。
