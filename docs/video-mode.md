# 视频模式

视频模式把整块手机屏幕变成 PC 主显示器：画面上直接用触控板手势操作鼠标，并保留一个语音悬浮球。需要接收端与 Android 都为 **0.4.0** 或更新版本；PC 设置页“允许手机查看屏幕”开启（默认开启）。

## 进入与退出

连接电脑后，点击顶部栏键盘图标左侧的显示器图标进入。进入后隐藏顶部栏、快捷键与系统栏，整屏只显示 PC 画面；从屏幕边缘滑动可临时呼出系统栏。

按系统返回键／返回手势，或点击左上角半透明按钮退出。该按钮同时显示实际帧率与控制连接 RTT；PC 光标移到其他显示器时提示“光标在其他显示器”。App 进入后台时停止传画面，回到前台后自动恢复；断线重连后同样自动续上。

## 画面规则

PC 画面在手机上从不旋转，横屏和竖屏使用同一条规则：**按高度填满、水平居中**。

| 手机方向 | 16:9 电脑画面的默认显示 |
|---|---|
| 竖屏（例如 9:20） | 高度占满，左右被裁掉，只显示中间部分 |
| 横屏（例如 20:9） | 完整显示，两侧留窄黑边 |

双指捏合以手指中心为焦点缩放画面，最小为完整显示整个 PC 画面，最大为 PC 像素的 3 倍（且至少为默认的 4 倍）。PC 光标移动到视图四周 12% 的边缘区时，画面平滑平移，让光标始终可见；捏合后的视野会保持，直到光标再次移动。旋转手机时重新套用默认规则，并尽量让光标留在画面内。

## 手势

与[触控板](touchpad-gestures.md)完全一致，唯一区别是捏合只缩放手机上的画面，不再向 PC 发送 Ctrl＋滚轮：

| 操作 | 效果 |
|---|---|
| 单指移动 | 鼠标相对移动（与触控板相同，不是点哪到哪） |
| 单指轻点 | 左击 |
| 双击后按住或移动 | 拖拽 |
| 两指轻点 | 右击 |
| 两指移动 | PC 滚轮 |
| 两指张开／合拢 | 缩放手机画面 |
| 三指上滑／下滑 | 任务视图与桌面操作 |

触控板灵敏度沿用本机设置。系统手势导航时，屏幕中部两侧边缘已尽量排除返回手势（Android 限制每侧最多 200dp）。

## 语音悬浮球

视频模式只保留一个语音入口：可拖动的悬浮球，位置单独保存在本机。它固定使用 PC 语音页中**第一个已启用的语音组**（新安装默认是单击语音输入 RightCtrl+L），不能在视频模式中切换组：

- 单击语音组：方形，轻点“说话”开始，再点“结束”。录音期间触控板的第一次点击只用于结束录音。
- 长按语音组：圆形，按住说话、松手结束。

颜色与电平环和下半区语音区一致；没有已启用的语音组时显示“禁用”。

## 画质

“连接与设置”中可选画质，下次打开视频模式时生效：

| 档位 | 输出 | 码率（60fps） |
|---|---|---|
| 流畅（默认） | 最高 1920×1080 | 约 12 Mbps |
| 清晰 | 原生分辨率，最高 2560×1440 | 约 20 Mbps |
| 省流 | 最高 1280×720 | 约 6 Mbps |

PC 画面只按比例缩小、从不放大，同时不超过手机 H.264 硬件解码器上限。只传 Windows 主显示器。

## 实现

| 环节 | 做法 |
|---|---|
| 截屏 | 内嵌精简 LGPL ffmpeg 的 `ddagrab`（DXGI 桌面复制），帧留在 GPU 上；`draw_mouse` 把光标画进画面 |
| 缩放 | NVENC／AMF 用 `scale_d3d11` 在 GPU 内缩放；Media Foundation 下载到内存后缩放 |
| 编码 | 依次探测 `h264_nvenc` → `h264_amf` → `h264_mf`（硬件 MFT，覆盖 Intel 核显），首个可用者缓存。超低延迟预设、无 B 帧、CBR、VBV 约两帧、GOP 1 秒 |
| 封装 | FLV 到标准输出：每帧带长度，收到即可转发，避免裸 H.264 流等下一帧起始码的一帧延迟 |
| 传输 | 独立的证书固定 WSS `/video`，与控制连接分开，大帧不会阻塞心跳与点击；积压超过约 100 ms（6 帧）丢到下一个关键帧 |
| 解码 | Android MediaCodec 异步模式直接输出到 SurfaceView；开启 `KEY_LOW_LATENCY` 与厂商低延迟开关，输出帧到达立即渲染 |
| 缩放显示 | 只改变 SurfaceView 的布局尺寸与位置，由系统硬件合成器缩放，不额外拷贝像素 |

ffmpeg 子进程放在“随句柄关闭而终止”的作业对象里，接收端退出或崩溃时一并结束。同一时间只有一部手机能查看屏幕，另一部请求时提示“另一台手机正在查看电脑画面”。协议细节见[控制协议](../protocol/README.md#video)，构建方法见下文。

## 构建内嵌 ffmpeg

`scripts/build-ffmpeg.ps1` 下载固定版本的 FFmpeg 8.1.3、nv-codec-headers 11.0.10.3（NVIDIA 驱动 456.71 及以上）与 AMF headers 1.5.3 源码包。它先校验 SHA-256，并用 FFmpeg 官方发布密钥核对源码签名，然后在一次性 Docker Ubuntu 24.04 容器（默认使用 Canonical 在 ECR Public 发布的官方镜像）内用 mingw-w64 静态交叉编译。

构建过程会确认 GPL／nonfree 均未启用，且 `ffmpeg.exe` 只依赖 Windows 系统 DLL。产物与 `manifest.json`（版本、源码地址与哈希、configure 参数）写入 `windows/internal/video/assets`。`build-windows.ps1` 在交付前核对资源哈希、两个接收端 `--apk-info` 读回的 `ffmpeg_sha256`，并写入 `release-manifest.json`。许可证见[第三方声明](../THIRD_PARTY_NOTICES.md)。
