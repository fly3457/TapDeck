# 三组语音配置（0.3.9）

PC“语音”页保留音频设备和音量设置，下方滚动区域固定提供三组。每组顶部有启用、名称与长按／单击类型；长按只显示一个触发热键，单击显示开始和结束两个热键。手动输入、单键选择、录入组合键均可用；切换类型保留隐藏字段。点击“保存并同步配置”后生效。

| 固定 ID | 默认名称 | 类型 | 触发／开始 | 结束 | 启用 |
|---|---|---|---|---|---|
| voice-1 | 单击语音输入 | 单击 | RightCtrl+L | RightCtrl+L | 是 |
| voice-2 | 长按语音输入 | 长按 | RightAlt | 松手释放 | 是 |
| voice-3 | GPT听写 | 长按 | Ctrl+Shift+M | 松手释放 | 否 |

名称去除首尾空白后不能为空，按 Unicode 码点计长：ASCII 为 1，其余为 2，累计最多 16。8 个汉字、16 个英文字符或等额度混排均可；超限会提示并阻止保存。尾音延迟是全局设置，默认 200 ms、范围 0–1000 ms。空热键仍表示仅传音。录音开始时保存当时的组和热键，直到正常结束、取消或断线；下一轮使用新配置。

手机按钮显示当前组名，启用 2–3 组时按 PC 顺序循环；只有 1 组时置灰，点击无操作和震动。全部关闭时显示“语音未启用”，录音和切换均禁用，键盘与触控板照常工作。准备、录音、停止时禁用切换。当前组被关闭后在空闲时回到第一组可用配置，录音中关闭所有组仍可正常结束当前录音。

本机用 `voice_profile_id` 保存选择，改名或换类型不改变身份。首次使用选择第一组已启用配置；升级时读取旧 `voice_mode`，优先匹配对应类型，再保存组 ID。

全键盘长按空格使用当前选中组，始终按住开始、松手结束。长按组按下／释放组合键，单击组开始／结束各发送一次组合键。空格手势保持长按语义，可同时操作触控板；通过方形控件启动的单击录音仍会消费第一次快捷键或触控板点击，仅停止录音。

## 配置与兼容

Windows 配置升级到 schema 3，`voice.profiles` 存储以上三个 ID，顺序固定。新安装采用表中默认值；schema 2 的单击开始／结束与长按热键（包括空键）分别迁入前两组，第三组使用默认值且关闭。更早配置先扩展旧四个快捷键，再迁移语音。音频、端口、快捷键等设置保留；鼠标基准仍按既有规则固定为 2。

迁移前将原始文件完整备份为 `config.v1.bak` 或 `config.v2.bak`；已有不同备份时追加 `.1`、`.2` 等后缀。校验、备份或保存失败均不替换原配置。无需重新配对。

控制协议保持 v2，`ready.features` 增加 `voice_profiles`；新手机发送 `mic_start.profile_id` 和 `revision`。无效／停用 ID 或过期 revision 返回关联 `recording` 的 `mic_error`，再同步最新配置，手机退出准备状态。详情见 [控制协议](../protocol/README.md)。

新手机连接未声明能力的旧 PC 时显示原有两组，并发送原来的模式请求。旧手机连接新 PC 时使用对应类型的第一组已启用配置；没有对应类型则明确报错，不执行其他组热键。旧字段 `hold_key`、`toggle_start_key`、`toggle_stop_key` 由当前组配置派生，以免出现两份配置来源。

## 验证入口

- `windows/internal/config/voice_test.go`：默认值、名称边界、迁移、备份、保存失败。
- `windows/internal/server/voice_test.go`：按 ID 路由、同类型不同热键、旧手机请求、过期配置与录音快照。
- `VoiceProfilesTest`：Unicode 名称、选择记忆、关闭后回退及旧 PC 配置。
- `DeviceTest.voiceProfilesWireSnapshotAndSpaceGesture`、`voiceProfileButtonsCycleDisableAndFreeze`：请求字段、手机手势、禁用反馈、录音中修改、重开后记忆和最长名称截图。
- 设置 `TAPDECK_UI_OUTPUT` 后运行 `go test ./cmd/tapdeck -run TestVoiceProfileEditorUI -count=1 -v`，可在屏幕外创建独立编辑器，验证字段保留并生成最小窗口截图，不启动接收端。

运行结果与硬件验收范围见 [验证记录](verification.md)。
