# 2026-11-05 视频延迟：准确统计与优化

问题：视频模式顶部显示 7–20 ms，但用户对比显示器与手机，双指滚动网页的体感延迟约 200–300 ms。

原因（已确认）：顶部数字是控制通道心跳的往返时间（RTT），只反映网络往返，不包括截屏、编码、发送排队、解码与显示，并不是画面延迟。

- [x] 梳理视频链路：ddagrab → NVENC/AMF/MF → FLV 管道 → Go 发送队列 → WSS → Android MediaCodec → SurfaceView
- [x] 电脑端：每帧前发送帧时间消息（类型 3，截屏到编码、发送排队、发送时刻），心跳回带 PC 墙钟 pc_us
- [x] 手机端：心跳对时（取最短往返样本）、按 pts 统计截屏编码 / 排队 / 网络 / 解码四段，顶部显示一秒中位数“延迟 X ms”，logcat 每 2 秒输出分段
- [x] 单元测试：Go 帧时间编码与截屏起点估计；Android 对时、四段相加、中位数去尖峰、解析
- [x] 升版 接收端 0.5.11、Android 0.5.11 / code 36，更新协议、视频模式文档
- [x] 官方构建、换上新接收端，实测分段延迟：静止约 30 ms，滚动 136–183 ms，瓶颈在截屏编码段（120–165 ms）
- [x] 定位：ffmpeg 单独输出到空设备时滚动只有 12–40 ms，积压在写入接收端的管道（默认约 4KB 缓冲）与 8 包输出队列
- [x] 修复：自建 4MB 输出管道 + `-thread_queue_size 2`；滚动实测降到多数约 42 ms，用户体感约六七十毫秒
- [x] 竖屏状态文字省去前缀，不再截断
- [x] 升版 接收端 0.5.12、Android 0.5.12 / code 37
- [x] 提交 Git
- [ ] 可选：截屏编码提到 120fps，再省约 8–10 ms（待用户决定）
